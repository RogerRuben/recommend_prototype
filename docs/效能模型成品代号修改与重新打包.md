# 效能模型成品代号修改与重新打包

## 正确修改位置

`product_code`由本次输入的效能Workbook读取。打开原始Workbook，在`项目信息`工作表填写：

```text
A1：成品代号    B1：AIRCRAFT_DOOR_LOCK
A2：成品名称    B2：航空舱门锁
```

不能只修改已经生成的`effectiveness_runtime_manifest.json`。

## 推荐方式：运行BAT

关闭正在运行的效能服务后，在项目根目录双击：

```text
PACKAGE_EFFECTIVENESS_SERVICE_MODEL_WIN7.bat
```

每次运行都会重新询问，不再继承旧的`EFFECT_WORKBOOK`环境变量。依次填写：

1. 效能专家交付的原始源码目录；
2. 已修改的原始Workbook完整路径；
3. 专家State完整路径，基线模型可以留空；
4. 期望的`product_code`，建议必填。

输入源码、Workbook和State不能放在输出目录`services\effectiveness_service\model\current`内，因为该目录会被完整替换。

成功后脚本输出JSON。必须核对其中：

```json
{
  "status": "PASS",
  "input_workbook": "本次实际读取的文件",
  "product_code": "期望的新代号",
  "state_mode": "learned_state"
}
```

如果Workbook里的代号不是输入的期望代号，打包器会报错并保留上一个可用运行包。

## Python命令

### Windows CMD

CMD可以使用`^`续行：

```bat
runtime\venvs\model_runtime38\Scripts\python.exe -m services.effectiveness_service.package_effectiveness_runtime ^
  --source-root "D:\effectiveness_project\source" ^
  --workbook "D:\effectiveness_project\data\door_lock.xlsx" ^
  --state "D:\effectiveness_project\state\state_xxx.json" ^
  --output "services\effectiveness_service\model\current" ^
  --expected-product-code "AIRCRAFT_DOOR_LOCK"
```

### PowerShell

PowerShell不能使用`^`续行。最稳妥的是整条命令写成一行：

```powershell
runtime\venvs\model_runtime38\Scripts\python.exe -m services.effectiveness_service.package_effectiveness_runtime --source-root "D:\effectiveness_project\source" --workbook "D:\effectiveness_project\data\door_lock.xlsx" --state "D:\effectiveness_project\state\state_xxx.json" --output "services\effectiveness_service\model\current" --expected-product-code "AIRCRAFT_DOOR_LOCK"
```

## 打包后检查与重启

先直接检查新Manifest：

```powershell
(Get-Content services\effectiveness_service\model\current\effectiveness_runtime_manifest.json -Raw | ConvertFrom-Json).product_code
```

必须关闭旧的18102效能服务进程并重新启动。已经运行的服务不会自动重新加载磁盘上的模型包：

```text
START_EFFECTIVENESS_SERVICE_WIN7.bat
```

随后访问`http://127.0.0.1:18102/api/v1/schema`，检查返回的`product_code`。如果Manifest已经是新值、HTTP仍是旧值，说明旧服务窗口或旧进程尚未关闭。
