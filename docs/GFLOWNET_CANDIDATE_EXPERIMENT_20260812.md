# GFlowNet 候选集生成实验（2026-08-12）

## 结论

当前不应使用 GFlowNet 替换 V19.6.8 的耦合感知深度搜索。

在航空舱门锁演示数据、价格下界向外 5% 的同预算测试中，现有深度束搜索找到的最低预测价格为
`12.216221 万元`；3 次 GFlowNet 独立运行的最低价格为 `12.318484～12.457468 万元`，均未满足
`12.019971 万元`的严格目标。因此，GFlowNet 没有改善当前最重要的“深度越界命中能力”。

GFlowNet 可以作为可选的多样性补充器：保留深度束搜索的最优点，再从 GFlowNet 样本中选择与已有方案
距离足够远的方案。该组合测试返回价格 `12.216221、12.318484、12.321623 万元`，三组属性距离为
`0.431570、0.557900、0.353553`。但这意味着追加模型调用，不能把它表述成同预算下的优化收益。

## 测试设计

- 历史成品：`basic_aircraft_door_lock_history_demo.xlsx`，12 条。
- 历史模型预测价格区间：`12.652601～19.631945 万元`。
- 目标价格上限：`12.019971 万元`，比历史预测下界低 5%。
- 两种算法均使用 360 个唯一候选的价格、效能 HTTP 联合评估。
- GFlowNet 使用 3 个固定随机种子独立复测，每条轨迹最多修改 4 个属性。
- 每个终态仍调用现有 `_finalize_params`，所以没有绕过耦合推导、约束修复、编码映射、物理门和业务规则。

## 结果

| 方法 | 独立运行 | 最低预测价格（万元） | 严格命中 | 耗时 | HTTP 批次 |
|---|---:|---:|---:|---:|---:|
| 现有深度束搜索 | 1 | 12.216221 | 0 | 15.703 秒 | 8 |
| Tabular TB-GFlowNet | 种子 20260812 | 12.319175 | 0 | 7.494 秒 | 29 |
| Tabular TB-GFlowNet | 种子 20260813 | 12.318484 | 0 | 5.860 秒 | 16 |
| Tabular TB-GFlowNet | 种子 20260814 | 12.457468 | 0 | 5.264 秒 | 13 |

GFlowNet 三次最低价均值为 `12.365042 万元`。虽然本机墙钟时间较短，但它需要更多小批量 HTTP 请求；在甲方
较慢的 Win7 机器上，该时间优势不能直接外推。第三次运行的结果明显变差，也说明这版在线表格策略尚不稳定。

## 原型是什么

原型位于 `app/gflownet_generator.py`，使用不依赖 PyTorch 的表格型 Trajectory Balance：

1. 状态由“历史成品种子 + 无序属性修改集合”组成。
2. 前向动作选择历史种子、为尚未修改的属性赋值、或停止。
3. 反向动作均匀移除一个修改；同一成品可由不同修改顺序到达。
4. 使用 `logZ + log P_F - log P_B - log R` 的 Trajectory-Balance 残差训练策略。
5. 奖励由真实价格服务、真实效能服务、价格目标、物理门及规则错误共同决定。

这样可以验证 GFlowNet 的核心机制，又不会为 Win7 离线交付立即增加 PyTorch 和大体积 wheels。

## 建议的后续组合方式

只有在用户要求更多不同方案，或深度搜索返回的有效候选数量不足时，才启用可选补充流程：

1. 快速/浅层越界继续只运行现有搜索。
2. 深度越界先运行现有耦合感知多阶段束搜索，保留价格前沿精英。
3. 仍需扩充方案时，以历史成品和束搜索精英为起点运行 GFlowNet。
4. 合并候选后再次执行现有规则、物理门和双模型评估。
5. 保留目标最优方案，再按归一化属性距离进行 max-min 多样性选择。

在进入正式推荐链路前，至少还需满足以下门槛：

- 5～10 个不同成品数据集上，前沿指标不劣于现算法；
- 多随机种子的最低价/目标差距波动可控；
- 对离散、多类别、连续变量和强耦合规则分别做消融测试；
- 按总双模型调用次数和端到端时间比较，而非只比较算法循环时间；
- 策略缓存必须绑定成品、参数结构、编码字典、价格模型和效能模型的散列，任何一项变化即失效。

## 复现

在项目根目录运行：

```powershell
runtime\venvs\aircraft_door_lock38\Scripts\python.exe tests\price_boundary_generation_benchmark.py
```

该测试会临时启动独立价格与效能 HTTP 服务，不修改正式数据库；运行结束后自动关闭服务并删除临时目录。
