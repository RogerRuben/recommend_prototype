# V19.4 需求锚定与混合属性目标搜索引擎

## 核心原则

学习得到的可行轮廓是历史经验与模型适用域的参考，不是覆盖用户需求的硬边界。

当用户明确要求某项技术属性时，生成器先把最相似历史方案投影到该目标并锁定该属性。后续搜索只能调整其他允许自动调整的属性，不能为了回到经验轮廓而修改用户目标。

## 与V19.1的主要差异

V19.1采用历史种子附近的相关随机采样，并会把超出轮廓的目标属性拉回经验区间。V19.4沿用并扩展为：

```text
相似历史种子
→ 用户技术条件投影并锁定
→ 计算锁定目标的经验轮廓偏离
→ 反向搜索能够补偿的其他属性
→ 显式耦合与硬约束修复
→ 双模型评价
→ 改进候选成为下一轮搜索中心
→ 返回需求满足方案或明确标注风险的探索方案
```

## 自适应邻域

每一轮同时使用四类邻域：

1. **反向轮廓邻域**：对轮廓模型的源属性做有限差分试探，优先保留能降低锁定目标轮廓偏离的方向；
2. **单属性邻域**：对优先补偿属性分别执行上调和下调；
3. **双属性联动邻域**：对两个补偿属性进行同向或反向联合调整；
4. **相关联合邻域**：按相似历史样本估计的相关结构生成联合扰动。

搜索采用多起点束搜索。每轮保留较优且具有差异的候选作为下一轮中心，扰动尺度按轮次逐步缩小。

## 候选比较顺序

候选按以下词典序优先级比较：

1. 明确工程硬约束冲突；
2. 用户筛选条件未满足程度；
3. 模型经验轮廓偏离；
4. 模型训练域异常程度；
5. 价格、效能、可行概率和效费比；
6. 相对历史种子的修改距离。

## 外推方案

当用户目标位于历史经验范围之外时，系统仍然调用价格和效能模型。结果会同时返回：

- 用户目标是否满足；
- 经验轮廓上下限与偏离量；
- 价格和效能预测；
- 训练域异常状态；
- 高、中、低预测可信度；
- 哪些其他属性被用于补偿。

若用户目标满足但超出经验轮廓，方案标记为“需求满足·外推评估”，而不是“生成失败”。

若与明确工程硬约束冲突，方案标记为“探索方案”，并明确说明不能直接用于工程实施。

## V19.4：混合属性、模型输出目标与标签规则驱动

V19.4在需求锚定和反向轮廓补偿基础上，统一混合属性合法域，并主动搜索模型输出目标与标签目标。

### 混合属性合法邻域

生成器根据DataMaster中的搜索类型分别构造合法邻居：连续属性按步长试探，整数属性按整数级移动，有序离散属性按等级相邻或穷举，无序枚举逐项切换，布尔属性显式翻转。筛选、编辑、生成、保存校验和模型输入使用同一属性定义。

价格上限等目标会先扫描全部可调属性。多个邻居都能满足目标时，优先选择改动幅度更小的合法邻居，再将有效调整组合成后续搜索中心。

### 当前草稿动态评估

编辑生成方案后，系统重新计算价格、效能、标签、需求满足情况、耦合、约束、经验轮廓、域外风险和可信度。右侧提示不再沿用初始生成时的静态状态；初始生成来源仅用于追溯。

### 模型输出目标

用户设置价格上限、最低效能、最低效费比或最低可行概率时，生成器不再只在候选完成后判断是否满足，而是对允许调整的字段执行有限差分试探，比较每个局部动作对目标差距的改善程度，并形成单字段、双字段和工程边界邻域。

### 标签规则目标

每个选中标签读取DataMaster中的规则组。同一规则组内部按AND组合，不同规则组按OR形成不同生成分支。规则可引用技术参数、预测价格、效能分和可行概率。生成后按最终参数重新判定，避免仅依赖历史标签继承。

### 稳定批次

每次生成结果保存在独立临时批次中。候选由`batch_id + candidate_id`稳定定位，新批次不覆盖旧批次，从而保证页面中已展示的候选可以继续打开和编辑。
