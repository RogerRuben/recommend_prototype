# 与用户提供的效能和价格代码的对齐说明

## 效能评估代码

原效能项目把数据组织为属性定义、历史方案、耦合关系和技术要求，并包含：

- 耦合经验带；
- 专家可行性模型；
- Bradley–Terry偏好模型；
- LP-UTA／加性效用评分；
- 主动学习候选生成；
- 专家证据和学习状态保存。

V19部署产物沿用“完整属性→耦合轮廓→可行概率→效能分”的结构。效能schema被定义为完整成品属性，不能缺少页面上专家能够修改的某项属性。

训练阶段可以继续使用原项目中的NumPy、SciPy或交互式工具；部署阶段把已经学习好的轮廓、系数、权重、训练范围和版本固化为JSON，由标准库直接加载。

## 价格预测Notebook

用户提供的价格Notebook包括：

- 数据清理和异常样本处理；
- 标准化；
- 对数价格；
- 多个候选回归器；
- 集成预测；
- 预测区间。

V19部署模型保持以下关键过程：

```text
原始价格输入
→ 与训练代码一致的派生特征
→ 保存的mean/scale标准化
→ 多个对数价格线性子模型
→ 保存的ensemble_weights集成
→ exp逆变换
→ residual_interval_log价格区间
```

运行时不读取目标价格，不重新拟合模型，不运行交叉验证，也不依赖Notebook状态。

## 缺失属性处理

原实验代码通常假设训练矩阵列完整，但部署系统必须面对协议字段缺失。因此V19在模型包外层增加`input_contract`：

- 完整效能属性缺失：直接拒绝；
- 价格模型共同属性：按价格模型声明处理；
- 价格特有属性：可由方案输入、数据管理配置或模型保存的训练统计量提供；
- 填补记录：显式返回，降低预测可信度；
- 任何缺失都不默认解释为0。

## 模型格式

V19当前演示产物使用JSON而不是`.pkl`，原因是：

- Windows 7／Python 3.8部署更稳定；
- 不依赖训练机的scikit-learn版本；
- 特征顺序、预处理、缺失策略和系数可审查；
- 便于SHA-256校验和版本回滚。

真实价格模型若最终必须使用树模型或XGBoost，可以改成独立运行时，但仍应输出相同业务字段并保留独立input_contract。当前V19仅承诺兼容随包JSON集成模型格式。
