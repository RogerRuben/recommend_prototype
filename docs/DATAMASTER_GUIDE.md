# V19 DataMaster维护指南

## 设计原则

SQLite是运行时唯一权威数据源；DataMaster是非程序人员使用Excel批量维护和迁移主数据的标准载体。推荐、风险提示和生成器只读取数据库，不读取固定Python常量。

## 推荐入口：先上传普通历史成品表

如果手里已经有“每行一个历史成品、每列一个属性，并包含历史价格”的 CSV/XLSX，不需要先手工建立 DataMaster 下拉字典：

1. 打开数据管理中心的“待发布成品”；
2. 在“从历史成品表自动建立草稿”中填写成品代号、名称和缺失识别符；
3. 上传普通 CSV/XLSX，先点“仅分析预览”；
4. 确认推断摘要后，点“按推断结果建立草稿”；
5. 可在页面逐条编辑，也可下载“自动维护工作簿”，在 Excel 中修改后回导同一草稿。

系统自动处理：

- 空单元格始终按缺失处理；可另外指定 `-1`、`\`、`/` 等缺失符；
- 只要某个属性在任一成品中缺失，该属性就先标为“非必填”；
- 列名含“是否、有无、启用、支持”等语义时，0/1 推断为有/无；
- 含义不明确的 0/1 不会武断转换成有/无，而是保留为枚举并标记“需要人工确认”；
- 少量文字取值推断为枚举，数值列推断类型、历史范围和小数位；
- 标签、规则、耦合和约束可暂时为空，后续分别维护。

自动推断只是草稿建议，不是模型事实。对于中文列名，系统可能生成 `attr_001` 一类临时字段编号；在训练或绑定正式模型前，应改成稳定、可追踪的英文业务字段 ID。

草稿建立、工作簿回导和业务数据切换都不读取价格/效能模型 Schema，也不调用模型 HTTP 接口。“检查业务数据（可选）”只检查本工作簿内部结构和引用关系。切换后如果业务成品与当前双模型服务不一致，只暂停推荐和计算，不影响继续维护、下载或再次切换数据。

## 工作表

### 成品信息

当前一个DataMaster对应一个业务成品。它可以先于新价格/效能服务准备完成，`product_code`不要求与当时正在运行的旧服务一致。

### 指标定义

维护专家可以修改的全部效能属性，包括中文名、单位、取值类型、上下限、效能方向、说明、调整提示和允许值。

`允许自动调整`是生成器唯一需要用户维护的生成开关：

- 是：生成器可以在历史局部分布和规则允许范围内改变该指标；
- 否：生成器从历史种子继承，不自动改变。

系统不要求用户填写扰动比例、生成顺序或复杂条件公式。

### 标签字典与标签规则

标签判定方式：

- 规则判定：根据标签规则自动判断新生成方案是否具有该标签；
- 从种子继承：从历史种子继承；
- 人工维护：仅历史协议或人工录入使用，生成器不会自动声称满足。

同一标签、同一规则组中的规则是AND；不同规则组之间是OR。

### 耦合关系

支持正向、负向和可行域三类。正向/负向关系用于联合调整方向与风险提示；可行域关系用于自动修复和硬边界检查。

### 约束规则

通用形式：

```text
左侧指标 关系 系数 × 右侧指标 + 偏置
```

右侧指标留空时表示与常数比较。

### 历史协议

一行一份协议，一列一个成品属性。属性可暂时为空，可在维护工作簿或数据中心逐条补充。切换业务数据时不会为适配当前模型强制补0、补下限或补训练均值；点击计算时再由目标HTTP模型服务决定其输入是否足够。

### 模型字段绑定

这是计算侧诊断/配置页，不是业务属性主表，也不参与业务数据检查与切换。服务就绪后可从其Schema同步；价格特有的固定运行值也可在此配置。

## 导入流程

```text
导出当前DataMaster
→ 在Excel中维护
→ 上传并解析预览
→ 修正无法写入的格式或本地引用错误
→ 切换业务数据
→ 自动备份旧数据库
→ 替换主数据和历史协议
→ 刷新推荐与生成缓存
```

DataMaster只检查：一条成品信息、业务字段基本类型、编号唯一性、标签引用、耦合引用、约束引用和协议引用。它不检查当前模型成品、模型字段并集、共享字段单位或模型必填性。
