# 甲方部署与成品更换流程（原始成品表＋价格模型＋效能模型）

适用环境：Windows 7 64 位、Python 3.8 64 位、甲方电脑断网。本文对应“不在源码包中携带离线 wheels”的交付方式。

## 1. 最终交付物

建议向甲方交付两个文件，并通过独立渠道提供 SHA-256：

1. `IndustrialProtocolDemo_V19_6_V11_Source_NoWheels_20260812_R4.zip`：推荐主系统、两个模型服务、安装/启动/回滚工具、测试和文档，不含 wheels、虚拟环境和开发缓存。
2. `<成品代号>_delivery.zip`：由历史成品表、价格原生模型和效能原运行包组成的统一成品包；同目录必须带 `.sha256`。

源码包与成品包分离。以后更换成品时通常只需重新制作第二个包，不必重新复制整套程序。

## 2. 模型制作电脑仅有三项输入时如何打包

准备以下文件：

- 历史成品表：普通 `.xlsx` 或 `.csv` 宽表，至少包含成品编号/名称、价格和各项属性；
- 价格模型：`price_native_bundle.pkl`，建议同时保留同名 `.manifest.json`；
- 效能模型：包含 `effectiveness_runtime_manifest.json`、`source`、`data`、`state` 的完整目录。

在项目根目录执行：

```bat
BUILD_DELIVERY_FROM_HISTORY_WIN7.bat ^
  incoming\历史成品.xlsx ^
  incoming\price_native_bundle.pkl ^
  incoming\effectiveness_runtime\effectiveness_runtime_manifest.json ^
  exports\PRODUCT_A_delivery.zip ^
  PRODUCT_A ^
  产品A
```

也可以直接调用通用入口：

```bat
BUILD_PRODUCT_DELIVERY_WIN7.bat ^
  --history-workbook incoming\历史成品.xlsx ^
  --price-model incoming\price_native_bundle.pkl ^
  --effectiveness-package incoming\effectiveness_runtime\effectiveness_runtime_manifest.json ^
  --product-code PRODUCT_A ^
  --product-name 产品A ^
  --missing-tokens=-1,\,/ ^
  --output exports\PRODUCT_A_delivery.zip
```

构建器会自动完成：

1. 解析历史成品表和缺失标识；
2. 推断布尔、数值、IP 等级、枚举和文本属性；
3. 自动建立 `attr_001`、`attr_002` 等稳定字段编号；
4. 将模型使用的字段标记为模型字段，备注等业务字段继续保留；
5. 比较价格模型、效能模型和业务数据的成品代号、字段、类型与单位；
6. 生成统一 ZIP 和同目录 `.sha256`。

如果模型字段编号不是按历史表属性顺序生成的 `attr_XXX`，应先在数据制作电脑调整模型 Schema 或业务草稿字段编号。打包器不会根据相似中文名称擅自绑定不同字段。

## 3. 业务值到模型编码的处理

历史表保留用户熟悉的业务值，模型调用前再编码。例如：

```json
{
  "是": 1,
  "否": 0,
  "类型1": 0,
  "类型2": 1,
  "类型3": 2
}
```

系统会自动处理：

- 是/有/启用/支持 → `1`；
- 否/无/停用/不支持 → `0`；
- 当业务允许值为连续的“类型1、类型2……”且模型允许值为连续数字编码时，按顺序生成零基或模型声明的编码；
- 业务值与模型值本来相同时不做转换。

不能无歧义推断时不会强行编码。操作人员可在“数据管理中心 → 指标定义 → 业务值→模型值映射”中维护 JSON，也可在 DataMaster 的“指标定义”工作表最后一列维护“模型取值映射(JSON)”。映射只用于模型请求，页面、数据库、导出表仍显示业务值。

## 4. 甲方电脑基础环境

1. 将源码包解压到短路径，例如 `D:\IPDemo`，不要放在桌面深层目录。
2. 安装 64 位 Python 3.8，建议所有电脑使用一致安装路径。
3. 本源码包不含 wheels。断网电脑必须采用以下一种已批准方式准备依赖：
   - 在联网或内网镜像环境执行 `INSTALL_SOURCE_DEPENDENCIES_WIN7.bat`；
   - 单独提供经过验收的 `runtime\venvs\model_runtime38`；
   - 单独提供由项目要求版本制作的 wheels，再按离线流程安装。
4. 运行 `VERIFY_MODEL_ENVIRONMENTS.bat`，确认 Python、NumPy、SciPy、scikit-learn、openpyxl 和当前模型可以加载。

不能在目标机既断网、又没有虚拟环境、也没有 wheels 的情况下安装第三方依赖；这三项条件至少要满足其一。

## 5. 在甲方电脑验包和安装成品

把成品 ZIP 和 `.sha256` 放到 `D:\IPDemo\deliveries`。先关闭 17891、18101、18102 三个服务，再执行：

```bat
VERIFY_PRODUCT_DELIVERY_WIN7.bat deliveries\PRODUCT_A_delivery.zip --expected-sha256 已确认的64位摘要
```

验证通过后安装：

```bat
INSTALL_PRODUCT_DELIVERY_WIN7.bat deliveries\PRODUCT_A_delivery.zip --expected-sha256 已确认的64位摘要
```

安装器会先备份当前价格模型、效能模型和 SQLite，然后：

- 把价格模型安装到 `services\price_service\model\price_native_bundle.pkl`；
- 把效能运行包安装到 `services\effectiveness_service\model\current`；
- 把历史成品数据导入数据中心为草稿；
- 返回备份编号和草稿编号。

安装不会自动激活草稿，避免未经业务人员确认就切换当前成品。

## 6. 启动和激活

1. 运行 `START_ALL_SERVICES_WIN7.bat`。
2. 检查：
   - `http://127.0.0.1:18101/health` 的 backend 为 `native_pickle`；
   - `http://127.0.0.1:18102/health` 的 backend 为 `original_effectiveness_runtime`；
   - 两个 `/api/v1/schema` 的 `product_code` 一致。
3. 打开 `http://127.0.0.1:17891/admin`。
4. 进入“成品数据工作区”，打开安装器导入的草稿。
5. 检查自动推断字段、非必填字段、枚举允许值和模型取值映射；需要时直接在页面或维护工作簿中修正。
6. 执行业务数据检查，然后由业务人员点击激活。
7. 重启推荐主系统，使当前业务数据和双模型 Schema 完成同步。

## 7. 功能验收顺序

1. 不设置条件执行历史智能推荐，确认历史方案能返回；历史数据会通过一次批量双服务请求完成评价。
2. 设置价格、效能、可行概率或标签条件，启动生成任务；生成在后台进行，页面可继续操作。
3. 打开一个方案，修改属性后点击“重新计算价格与效能”。属性变化本身不会自动调用模型。
4. 点击“改进搜索”：
   - V11 效能包使用模型原生反事实改进；
   - V10 固定协议包使用主系统的双服务批量邻域兼容搜索，不再调用模型不支持的接口。
5. 用包含中文“是/否”或“类型1/类型2”的成品验证编码，确认页面仍显示中文，模型计算成功。
6. 保存一个专家方案并重新打开。

## 8. 性能说明

当前版本采用三层优化：

- 历史方案由逐条 HTTP 改为一次批量价格/效能评价；
- 候选生成采用批量方向束搜索：先生成覆盖各属性方向、边界和离散值的探针，每一轮只进行一次双模型批量评价，不再在搜索中心内部隐藏重复试算；
- 原生价格模型对整批候选执行矩阵预测，每个集成子模型每批只调用一次；
- 搜索预算按请求数量自适应，并在已有足够数量、能够通过最终差异性筛选的严格新候选后提前收敛。

基础航空舱门锁测试数据在“中等偏低价格上限、生成3个严格候选”的双HTTP服务测试中约用2.04秒，执行2轮批量评价且没有隐藏的逐方案模型调用。该数值是开发机夹具结果，不作为甲方正式模型的固定性能承诺。

### 快速搜索与深度越界探索

系统会自动比较用户筛选条件与历史成品边界，无需操作人员选择算法：

- 历史范围内或单项浅层越界不超过3%：继续使用快速批量方向束搜索；
- 单项越界超过3%，或两个及以上筛选维度同时越界：自动使用深度越界搜索；
- 深度搜索先保留完整快速搜索结果，再按轮进行多属性组合、精英交叉、局部收敛和差异化补充，默认最多7轮、至少360个候选；
- 找到足量严格解会提前结束；找不到时返回最接近的探索方案，不会将未满足条件的方案标成合格。

进入深度模式时页面会立即提示：当前筛选条件越界较多，等待时间会比普通生成更长；价格、效能和可行性均属于模型外推预测，仅供方案探索与专家复核参考。

航空舱门锁夹具中，历史最低预测价为12.6526万元。越界1%～3%的快速搜索约3.6～3.7秒；越界5%时深度搜索约17.4秒、7轮360候选，最优探索价格约12.2162万元。目标12.0200万元未达到，因此结果被明确标记为探索方案。正式成品的耗时和可达范围取决于属性数、正式模型复杂度、历史数据和甲方硬件。

速度仍取决于正式模型本身、历史数据量、属性数和候选数量。甲方机器建议先用 5～10 个生成方案验收；正式使用再根据实际耗时调整。

## 9. 回滚

如果安装或验收失败，关闭三个服务，使用安装时返回的备份编号：

```bat
ROLLBACK_PRODUCT_DELIVERY_WIN7.bat 备份编号
```

回滚会恢复安装前的模型和 SQLite，并在覆盖当前状态前再保留一份安全快照。

## 10. 日常更换新成品

以后更换成品只重复以下步骤：

1. 准备新历史成品表、新价格模型、新效能运行包；
2. 用 `BUILD_DELIVERY_FROM_HISTORY_WIN7.bat` 构建新成品 ZIP；
3. 在制作电脑执行 verify；
4. 复制 ZIP、`.sha256` 到甲方电脑；
5. 停服务、安装、启动模型服务、检查 Schema；
6. 在数据中心复核草稿和映射；
7. 人工激活并完成验收；
8. 保留交付 ZIP、摘要、安装备份编号和验收记录。

数据草稿与模型部署仍然解耦：可以先维护数据，也可以先安装模型；只有推荐和显式计算要求当前业务成品与两个模型服务匹配。
