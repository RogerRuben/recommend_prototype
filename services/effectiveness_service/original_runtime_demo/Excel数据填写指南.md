# Excel 数据填写指南

本文面向负责准备项目数据的专家、工程师和数据管理员。它只说明一件事：怎样准备一个能被软件正确读取的项目 Excel。

当前示例文件：

```text
compare/demo/data/aircraft_door_lock_demo.xlsx
```

最稳妥的做法是复制这个示例文件，在副本中替换属性、方案和耦合关系。

## 1. 工作簿必须包含什么

Excel 格式必须是 `.xlsx` 或 `.xlsm`。

工作簿支持四个工作表：

| 工作表 | 是否必须 | 用途 |
|---|---|---|
| `方案数据` | 必须 | 放已有方案及其参数，第一行决定软件显示哪些属性 |
| `属性配置` | 强烈建议 | 说明单位、范围、设计顺序和效能偏好 |
| `耦合关系` | 按需要 | 说明哪些参数会单向影响其他参数 |
| `新技术协议` | 按任务需要 | 每行填写一份协议的各属性要求值，作为最终评分的100分参考 |

工作表名称要完全一致。可以增加其他说明工作表，软件会忽略它们。

## 2. 填写“方案数据”

### 2.1 第一行决定全部属性

第一行是表头。除系统保留列外，其他列都会被当成设计属性，并按照从左到右的顺序显示在 A/B 方案中。

建议表头结构：

| 方案编号 | 来源 | 已知可行性 | 属性1 | 属性2 | 属性3 | ... |
|---|---|---|---:|---:|---:|---|
| S-001 | 已有实物样本 | 未标注 | 50 | 1.4 | 8.2 | ... |
| S-002 | 历史设计 | 未标注 | 55 | 1.5 | 8.8 | ... |

可识别的系统保留列：

| 推荐表头 | 作用 | 是否必须 | 填写建议 |
|---|---|---|---|
| `方案编号` | 方案唯一编号 | 否 | 建议填写，例如 `S-001`；留空时系统自动编号 |
| `来源` | 样本来源说明 | 否 | 例如“已有实物样本”“历史设计”“试验件” |
| `已知可行性` | 来源备注 | 否 | 当前版本只保存和展示，不直接参与模型训练 |
| `备注` | 其他说明 | 否 | 可记录批次、资料编号等 |

`方案ID`、`ID`、`source`、`可行性标签`、`notes` 也能识别，但建议统一使用上表中的中文表头。

### 2.2 属性列填写规则

1. 属性名不能重复，也不能留空。
2. 每个方案的每个属性都必须有值，不能用空白表示“不知道”。
3. 数值属性只填写数字，单位放在“属性配置”，不要在单元格里写 `50 kN`。
4. 整数属性不能出现小数。
5. 类别属性填写一致的类别名称，例如“机械式”“电磁式”，不要混用近义写法。
6. 同一列必须保持同一种数据含义和单位。
7. 方案编号不能重复。
8. 完全空白的数据行会被忽略，半填的数据行会报错。

### 2.3 当前版本对已有方案的假设

软件把“方案数据”中的已有方案当作弱可行正例，用来形成工程经验分布，但不会把它们当作高效能方案。

因此：

- 优先放真实制造过、试验过、服役过或至少经过工程确认的方案；
- 不要把明确不可能实现的随机组合混在这里；
- 如果某个方案只是未知或待确认，可以保留，但应在专家交互中重新判断；
- 当前 `已知可行性` 列不会自动改变这个弱正例假设。

## 3. 填写“属性配置”

每个属性一行，`属性名` 必须与“方案数据”第一行完全对应。

推荐表头顺序：

| 属性名 | 属性ID | 单位 | 数据类型 | 设计顺序 | 显示精度 | 生成下限 | 生成上限 | 可行下限 | 可行上限 | 偏好方向 | 边际规律 | 参与效能 | 参与生成 | 说明 |
|---|---|---|---|---:|---:|---:|---:|---:|---:|---|---|---|---|---|

### 3.1 每一列怎么填

| 列名 | 是否建议必填 | 可填写内容 | 软件中的作用 |
|---|---|---|---|
| `属性名` | 必填 | 与方案表表头一致 | 用于匹配属性 |
| `属性ID` | 强烈建议 | 英文字母开头，只含字母、数字、下划线 | 内部稳定标识，例如 `rated_load` |
| `单位` | 建议 | `kN`、`kg`、`ms`、`-` 等 | 页面显示与报告输出 |
| `数据类型` | 建议 | `连续`、`整数`、`类别` | 决定解析、输入和生成方式 |
| `设计顺序` | 强烈建议 | `1`、`2`、`3`，也可写第一批/第二批/第三批 | 生成器按照这个先后顺序设计参数 |
| `显示精度` | 建议 | 0 至 8 的整数 | 页面及生成方案的小数位数 |
| `生成下限` | 强烈建议 | 数值 | 生成器和归一化使用的外层范围 |
| `生成上限` | 强烈建议 | 数值 | 必须大于生成下限 |
| `可行下限` | 兼容保留 | 数值 | 当前版本不要求填写，运行时自动使用样本最小值 |
| `可行上限` | 兼容保留 | 数值 | 当前版本不要求填写，运行时自动使用样本最大值 |
| `偏好方向` | 效能学习必填 | `越大越好`、`越小越好`、`不参与` | BT 和 UTA 的效能方向 |
| `边际规律` | 建议 | 见下文 | 约束 UTA 分段曲线形状 |
| `参与效能` | 建议 | `是` 或 `否` | 是否进入效能评分 |
| `参与生成` | 建议 | `是` 或 `否` | 生成器是否主动改变该属性 |
| `说明` | 建议 | 普通文字 | 给专家和维护者解释参数含义 |

### 3.2 属性 ID 的规则

正确示例：

```text
rated_load
mass
trigger_force_2
```

错误示例：

```text
额定载荷
2nd_force
mass-kg
```

ID 必须以英文字母开头，只能包含英文字母、数字和下划线，并且不能重复。属性显示名称以后可以调整，但已经开始采集专家数据后，不建议修改属性 ID。

### 3.3 生成范围与可行范围的区别

```text
生成范围：软件允许搜索和展示的外层范围，也是生成器不会越过的边界
样本经验范围：软件从已有方案最小值和最大值自动得到的经验核心
```

通常应满足：

```text
生成下限 <= 可行下限 <= 可行上限 <= 生成上限
```

生成范围通常应比样本经验范围略宽，用来探索历史方案尚未覆盖的区域。经验范围外只表示“尚未由样本覆盖”，不直接等于不可行。专家认为生成范围过大或过小时，也可以在软件右侧“调整方案生成范围”中修改，软件会备份并直接写回 Excel。

### 3.4 三批设计顺序

- `1`：最先确定的需求、任务或总体参数；
- `2`：在第一批基础上确定的中间设计参数；
- `3`：受前面参数影响的结果或下游参数。

例如：

```text
额定载荷（第1批）
-> 结构安全系数（第2批）
-> 重量、触发力（第3批）
```

耦合关系不能从后批参数反向指向前批参数。例如第 3 批的“重量”不能在耦合表中作为源属性决定第 1 批的“额定载荷”。

### 3.5 偏好方向

当前效能模型稳定支持：

- `越大越好`：数值越大通常越有利；
- `越小越好`：数值越小通常越有利；
- `不参与`：不进入效能模型。

程序也能识别“区间型”，但当前 BT/UTA 主模型不会把它作为正式效能属性。真正需要“目标区间最好”时，应先与开发者确认建模方式，不要仅填写“区间型”就认为已经实现。

### 3.6 边际规律

常用写法：

| 写法 | 含义 | UTA 约束效果 |
|---|---|---|
| `边际收益递减` | 前期改善明显，后期逐渐饱和 | 后一段效用增量不大于前一段 |
| `低值改善逐渐饱和` | 对越小越好的属性，继续降低的收益逐渐减少 | 按效用方向施加递减约束 |
| `边际收益递增` | 后期改善价值更大 | 后一段效用增量不小于前一段 |
| `线性` | 各段斜率一致 | 相邻增量同时受递增和递减约束 |
| `待确认` | 暂无可靠形状知识 | 不额外限制相邻分段形状 |

边际规律描述的是效能偏好，不是物理耦合。物理上“载荷增加导致重量增加”应填在“耦合关系”，不能写成属性边际规律。

### 3.7 布尔列可接受写法

`参与效能`、`参与生成` 可写：

```text
是 / 否
1 / 0
true / false
yes / no
参与 / 不参与
```

建议统一使用“是”和“否”。

## 4. 填写“耦合关系”

每一行表示一条有方向的关系：

```text
源属性变化 -> 目标属性通常随之变化
```

推荐表头：

| 源属性 | 目标属性 | 方向 | 关系类型 | 先验系数 | 置信状态 | 说明 |
|---|---|---|---|---:|---|---|

示例：

| 源属性 | 目标属性 | 方向 | 关系类型 | 先验系数 | 置信状态 | 说明 |
|---|---|---|---|---:|---|---|
| 额定载荷 | 重量 | 正向 | 单调影响 |  | 方向已知，系数待学习 | 额定载荷提高通常需要更多结构重量 |
| 额定载荷 | 触发/解锁力 | 正向 | 单调影响 |  | 方向已知，系数待学习 | 载荷提高通常推高解锁需求 |

### 4.1 每一列怎么填

| 列名 | 填写要求 |
|---|---|
| `源属性` | 必须与“方案数据”第一行中的属性名一致 |
| `目标属性` | 必须与“方案数据”第一行中的属性名一致 |
| `方向` | 填 `正向` 或 `负向` |
| `关系类型` | 建议填“单调影响”，当前主要用于说明 |
| `先验系数` | 可以留空；若填写，符号必须与方向一致 |
| `置信状态` | 例如“已确认”“方向已知，系数待学习”“待确认” |
| `说明` | 说明物理原因、适用条件和信息来源 |

当前版本使用“方向”约束拟合系数符号。`先验系数`会做符号校验，但尚不会直接固定或拉近最终拟合系数；它主要用于记录后续扩展所需的先验知识。

### 4.2 耦合关系必须满足

1. 不能自己指向自己。
2. 同一条源到目标关系不能重复。
3. 所引用的属性必须存在。
4. 当前耦合拟合只支持数值属性。
5. 耦合图不能形成有向环。
6. 源属性的设计顺序不能晚于目标属性。
7. 一个目标有多个源属性时，需要足够的已有样本。

例如以下环路不允许：

```text
A -> B
B -> C
C -> A
```

## 5. 需要多少已有方案

程序的最低数学要求不等于工程上足够。

- 没有耦合关系时，至少要有一行完整方案才能读取；
- 样本少于 `k + 2` 时不会阻止软件启动，耦合目标会以“方向已知、强度待学习”模式运行；
- 样本较多时可以拟合条件经验带，样本很少时主要依靠定向生成和专家可行性判断学习；
- 属性多、耦合源多或样本分布窄时，应增加样本；
- 样本应覆盖实际设计范围，不能全部挤在一个很小区域。

效能学习所需的专家比较次数与属性数、UTA 分段数和判断噪声有关。软件会根据自由参数数给出建议训练对数，而不是仅根据 Excel 行数判断是否训练完成。

## 6. 一个可直接照着做的填写流程

1. 复制 `aircraft_door_lock_demo.xlsx` 为新文件。
2. 在“方案数据”第一行保留系统列，替换属性列名称。
3. 每行填写一套完整的已有设计参数。
4. 在“属性配置”中为每个属性建立且只建立一行配置。
5. 与工程人员确认单位和初始生成范围；样本经验范围由软件自动读取。
6. 确认每个属性是越大越好、越小越好还是不参与效能。
7. 确认三批设计顺序。
8. 在“耦合关系”中只填写有把握的方向，不知道系数可以留空。
9. 运行校验命令。
10. 校验无错误后再启动软件。

## 7. 启动前校验

在项目根目录运行：

```powershell
python .\compare\demo\project_excel.py "C:\路径\你的项目.xlsx"
```

校验会输出项目名称、属性数、方案数、耦合数和警告。

警告不一定阻止启动，但必须阅读。例如“范围由样本推断”表示当前范围只是暂定值，不适合作为正式工程边界。

## 8. 使用自己的 Excel 启动

```powershell
python .\compare\demo\interactive_project_app.py --workbook "C:\路径\你的项目.xlsx"
```

然后打开：

```text
http://127.0.0.1:8776
```

修改 Excel 后需要重启软件。软件按文件内容生成指纹；Excel 内容变化后会使用新的状态文件，防止不同版本的数据和专家判断混在一起。

## 9. 常见错误

### 提示缺少“方案数据”

工作表名称不一致。请确认不是“方案 数据”“Sheet1”或多了空格。

### 提示第一行表头重复或为空

同一属性名出现两次，或者中间有空表头。第一行每一列都必须有唯一名称。

### 提示属性配置未出现在方案数据

“属性配置”的属性名与“方案数据”第一行不一致。检查空格、斜杠、括号和全半角字符。

### 提示数据类型不支持

使用 `连续`、`整数` 或 `类别`。不要写“数字”“小数”等自定义词。

### 提示整数属性存在小数

把数据类型改为“连续”，或者把该列所有值改为整数。

### 提示生成下限必须小于生成上限

检查上下限是否填反，或是否误用了不同单位。

### 提示耦合关系存在有向环

重新确认因果方向。当前生成器需要明确的上游到下游顺序，不能处理循环依赖。

### 提示设计顺序冲突

源属性所属批次晚于目标属性。修改设计顺序或纠正耦合方向。

### 公式单元格被识别为空

程序以 `data_only=True` 读取 Excel 公式的缓存结果。请先在 Excel 中打开并重新计算后保存，或直接粘贴为数值。

### Excel 能读取但效能模型没有属性

确认属性的 `参与效能` 为“是”，且 `偏好方向` 为“越大越好”或“越小越好”。

## 10. 填表后的人工复核清单

- [ ] 单位在所有样本中一致
- [ ] 属性 ID 唯一且以后不随意修改
- [ ] 每一行都是完整参数组合
- [ ] 已有方案主要是工程上成立的方案
- [ ] 生成范围覆盖希望探索的区域但不过度放大
- [ ] 样本最小值和最大值能够代表当前已有方案覆盖范围
- [ ] 偏好方向描述效能，不是物理因果
- [ ] 设计顺序符合真实设计流程
- [ ] 耦合方向符合“源影响目标”的单向表达
- [ ] 耦合图无环且不从后批指向前批
- [ ] 校验命令已运行并阅读全部警告

## 11. 当前能力边界

- 类别属性可以读取和展示，但当前 BT/UTA 与耦合代理主要面向数值属性；
- `新技术协议`只接受每个属性的单个参考值；方向来自`属性配置`，不会在协议表重复填写；
- Excel 自由文本不会自动变成物理约束；
- 已有方案的“已知可行性”暂不直接训练模型；
- 真实项目在正式使用前，应由数据管理员和领域专家共同复核配置。

## 12. 如何填写“新技术协议”

该工作表可选。没有时，软件仍能学习物理可行性和通用BT/UTA效能，但无法给出“相对某份新协议”的最终分数。有该表时，协议参数组合固定为100分参考。

第一行采用横向表头：

| 协议编号 | 协议名称 | 属性1 | 属性2 | ... | 说明 |
|---|---|---:|---:|---|---|
| `REQ-2026-01` | XX型舱门锁新技术协议 | 对应属性要求值 | 对应属性要求值 | ... | 可选文字说明 |

填写规则：

1. `协议编号`只能使用英文字母、数字、下划线和连字符，并且不能重复。
2. 属性列名必须与`方案数据`第一行完全一致，顺序建议一致。
3. 每个参与效能的数值属性都必须填一个要求值，单位与`属性配置`一致。
4. 不填写方向、要求类型、上下限、容差、硬性要求、超额加分或复用阈值。
5. 方向由`属性配置`决定：越大越好时高于参考值可超过100分；越小越好时低于参考值可超过100分；`区间型`以协议值为最佳点，偏离两侧均扣分且不超过100分。
6. 可以增加多行协议。在界面“未知方案评分参考”中切换时，只改变评分，不会重训模型或清空判断。

软件使用不含协议表的“学习数据指纹”管理状态。只修改、新增或删除协议行后重新打开Excel，原有可行性证据、专家偏好、BT和UTA参数仍会自动沿用；修改属性、样本或耦合关系则会被视为学习数据变化。
